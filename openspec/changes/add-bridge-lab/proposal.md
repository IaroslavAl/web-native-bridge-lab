## Why

PER-85 needs evidence that React can change endpoints, response interpretation and UI without rebuilding an installed iOS app. The seed has mission documentation only; a bounded contract-first lab prevents two native business fetch methods from being mistaken for a reusable transport.

## What Changes

- Add a v1 request/response/error/cancel bridge with correlation, native-owned deadlines and bounded UTF-8 transport.
- Separate trusted WebView provenance from exact API origin policy, reject redirects and ambient credentials, revoke old document work.
- Add GET catalog and POST quote web scenarios with different JSON shapes and deterministic web-only build variants on one installed Simulator binary.
- Add opt-in loopback fixtures and owned start/status/stop, plus reproducible unit, security and real WKWebView acceptance gates.
- Establish independently reviewed OpenSpec and protocol artifacts before implementation. This foundation card supplies documents/schema/validation only; module work remains separate.

## Capabilities

### New Capabilities
- `http-transport`: bounded generic Foundation executor and transport/error contract.
- `webview-bridge`: versioned trusted document bridge, correlation and revocation.
- `web-scenarios`: React request construction, interpretation, UX and same-binary variation.
- `local-lab`: deterministic fixtures, clean lifecycle and honest reproducible acceptance.

### Modified Capabilities
None. There are no baseline implemented capabilities.

## Impact

Future implementation touches native/TransportPackage, ios, web, backend and scripts as assigned in docs/architecture.md. Foundation adds only OpenSpec/protocol/reference documentation and local validation tooling. No production auth, binary/file streaming, real-device/signing, cloud, native business models, BDUI platform or publication. Owner-approved scope is fixed; technical review is delegated, while owner RC/publication gates remain intact.
