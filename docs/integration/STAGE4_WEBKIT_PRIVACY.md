## Failure investigation and regression sensitivity

The helper test first failed for missing `require_stage4_events`, then passed with missing socket closure, forbidden destination, late success and ambient credential event mutations. No product implementation was needed for these assertions to pass.

The initial Swift compile exposed six async XCTest-autoclosure errors; these were corrected by awaiting into locals. The first real50-predecessor run passed48/49 but failed the combined navigation test's incorrect expectation of three navigation-delegate denials. A focused diagnostic run observed frame/main denials plus a WKUIDelegate creation callback. The revised test models production's absent UI delegate and labels new-window rejection at the WebKit layer. This was a harness assertion error, not a product security defect. The subsequent full50 run passed.

An ignored `git archive` snapshot plus the exact candidate test/runner overlays is used for negative controls: remove main-frame admission guard; omit navigation revocation; enable shared native cookie acceptance. Only that copied snapshot is mutated, never tracked production source. Its live-test command, observed failed assertions and resource cleanup are retained in the evidence JSON. These are deliberately failing controls, not a second candidate or a claim that mutation score is exhaustive.
